# 正式版本发布检查清单

当前准备版本为 v1.5.1。先完成源码、验证和可审阅的发布材料，再取得用户对本次具体版本的明确确认；确认前不推送版本标签、不公开新版附件。既有 v1.5.0、v1.4.1 标签与发行资产继续保留。

每次正式发布将本清单与 [更新验收矩阵](UPDATE_ACCEPTANCE.md) 的实际结果一同核对。任何必须项未通过，不发布“看似成功”的不完整更新。

## A. 版本和构建来源

- [ ] 根目录 `VERSION` 已更新，语义版本有效，当前构建源码无漂移。
- [ ] `docs/RELEASE_NOTES.md` 首行与版本一致，具体更新、兼容性、验证局限及附件经过审阅；完整包包含该文件，发布页使用同一正文。
- [ ] Single 与 Portable 来源相同源码、相同 `APP_VERSION`，构建身份分别嵌入。
- [ ] `update-manifest.json`、Portable `package-manifest.json`、About/帮助窗口的版本一致。
- [ ] CLI 与 helper 的嵌入入口身份正确，只有 GUI 允许自身安装。
- [ ] 正式标签恰为 `v<VERSION>`，用户已确认本地/Actions 试用结果后才推送。
- [ ] 已有同名 Release 不覆盖，不移动历史标签，不删除 v1.4.1 或其他历史资产。
- [ ] 合成新版 `--test-version` 构建与正式产物隔离，不进入正式发布包。

## B. 配置兼容

- [ ] 判断本次是否改变字段结构、类型、语义、名称或层级，并记录结论。
- [ ] 没有不兼容变化时保持 `CONFIG_SCHEMA`，新增可选设置使用默认值补齐。
- [ ] 若存在不兼容变化，提高 `CONFIG_SCHEMA` 并逐级实现所有仍支持旧 schema 的迁移。
- [ ] 当前/最老仍支持的配置样本可读取，缺字段有默认值，未知字段保留。
- [ ] 迁移前原始字节已备份，副本迁移后执行 schema/字段校验，再原子替换。
- [ ] malformed、迁移异常/中断、校验/写入失败不覆盖原配置。
- [ ] 程序回滚同时恢复旧配置，保留用户原设置值。
- [ ] 配置位置仍兼容 `%LOCALAPPDATA%\ZoteroPDFBookmarks\settings.json`。

当前生产 `CONFIG_SCHEMA=1`，迁移列表为空；测试注入 schema 2/3 不算已发布的配置版本。

## C. Single

- [ ] 官方 EXE 名能更新，改名后仍能更新。
- [ ] 移动目录、中文路径、空格路径及改名+移动场景通过。
- [ ] 更新使用当前实际 EXE 路径，安装后保持用户原名称，仍为 Single。
- [ ] 文件锁/其他实例、权限不足、磁盘不足均在修改程序前安全停止。
- [ ] 真实冻结新版完成 GUI/config/PDF 核心健康检查，收到有效回执才提交。
- [ ] 健康失败、替换失败和事务中断可恢复旧 EXE 与旧配置。
- [ ] 成功最终只有当前主 EXE，无旧 EXE、`.old`、`.new`、`.part`、下载包与事务备份残留。

## D. Portable

- [ ] 官方目录、改名目录、移动到其他路径/磁盘通过。
- [ ] 主 EXE 改名、目录+EXE 同时改名、中文/空格路径通过。
- [ ] 主入口安装映射到用户原 launcher 名，根目录与发行类型保持。
- [ ] ZIP 文件集合与 package-manifest 一致，每个文件大小和 SHA-256 通过。
- [ ] installed-manifest 初始化/更新正确，且不把本机安装状态打包发布。
- [ ] 新增/修改的程序文件正确写入，旧清单证明属于程序的废弃 DLL/资源清除。
- [ ] 用户 config、UserData、额外 PDF、txt 和自建目录保持原字节。
- [ ] 新包路径与未知用户文件冲突时拒绝覆盖。
- [ ] 文件锁/权限/中断/健康失败可恢复程序文件、清单与配置。
- [ ] 真实冻结成功/失败两条分支通过，成功后无废弃程序和临时事务残留。

## E. 安全与发行完整性

- [ ] APP_ID、variant、版本、stable 通道及 UPDATE_SCHEMA 全部校验。
- [ ] 下载只访问已允许的 GitHub HTTPS 地址，重定向目标先校验。
- [ ] ZIP 穿越、绝对路径、大小写重复、符号链接/目录联接、额外文件与错误哈希被拒绝。
- [ ] 无硬编码长期 GitHub Token、密码或其他凭据。
- [ ] 原有 PDF 预览/写入/备份/CLI/OCR 功能完整回归通过，测试只用临时合成输入。
- [ ] Single/Portable/CLI/helper 实际构建及嵌入身份、OCR/运行库/第三方许可检查通过。
- [ ] `SHA256SUMS.txt` 文件集合完整，update-manifest 两种资产的名字/大小/哈希与实际资产一致。
- [ ] 发布先建草稿、上传全部资产，核对名字/大小后才公开；任何前置检查失败均不发布。

本版采用 HTTPS + 清单身份/版本/协议校验 + SHA-256。Authenticode 与 manifest 签名列入后续工作，不把尚未实现的签名写成安全保证。

## F. 事务、回滚和清理

- [ ] 下载/验证失败不修改现有程序，不遗留无用的 owned 下载内容。
- [ ] helper 位于目标程序目录之外，所有相关进程退出和文件释放后才替换。
- [ ] 一个目标同时只有一个安装事务；全部旧文件与原配置在替换前备份。
- [ ] journal 原子、持久写入，逐操作先记录开始，再替换文件。
- [ ] GUI/config/core 健康回执包含正确 token、版本、类型、APP_ID 及实际目标进程。
- [ ] 程序与配置同步回滚；中断恢复通过，未批准 READY 不在下一次启动自动安装。
- [ ] 已提交事务的清理失败只延后清理，不错误回滚成功安装。
- [ ] 清理仅针对本 APP_ID 且状态可清理的事务，保护其他应用/未完成备份/用户未知文件。
- [ ] helper 本次退出后或下次启动可完全清理，失败诊断日志按最近 10 组保留。
- [ ] README、CHANGELOG、使用说明和实际验收记录与本次版本/行为一致。
